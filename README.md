# top-k

流式选出分数最大的前 K 名，只用 Go 标准库。

```
go test ./...
go run ./cmd/top-k --k 3 --generate 100 --held
```

## 口径（README 为准）

- **取分数最大的 K 个**：`--k 3 --generate 100` 现在给出的是分数最小的三个（25、32、35），
  按口径应该是最大的三个。
- 同分时按**键的字典序**从小到大排（稳定、可复现）；输出按「分数降序、键升序」排列。
- **内存 O(K)**：选择器内部保留的条目数不能随输入增长，喂 N 个条目后 `Held()` 应该是 O(K)
  的量级（例如 ≤ 2K），现在是 `held=100`（等于输入条数）。
- 推入时要**先用阈值剪枝**：分数低于当前第 K 名就直接丢，不进堆；`Compared()` 要能说明这一点
  （比较次数与输入条数是 O(N log K) 而不是 O(N log N)）。
- 不变量：`Top()` 的结果与「把全部条目排序后取前 K」逐项一致（分数与顺序都要一致）；
  K ≤ 0 时返回空；输入不足 K 个时返回全部；同一输入重复执行结果相同。
- 规模：100 万条输入、K=100 时内存 O(K)，总比较次数 O(N log K)。

## 实现

- `Selector` 内部是一个容量 K 的**最小堆**（手写，零依赖），堆顶恒为当前第 K 名
  （最差的入围者），`Held() = min(K, N)`，内存 O(K)。
- `Push` 时堆已满就先和堆顶（阈值）比一次，不优于阈值直接丢弃、不进堆；
  否则替换堆顶并下沉。每条目 O(log K) 次比较，总量 O(N log K)，
  由 `Compared()` 统计，并有严格上界 `N(1 + 2⌈log₂(K+1)⌉)`。
- 排序口径：分数低更差；同分键的字典序大更差。`Top()` 从堆拷贝出结果，
  按「分数降序、键升序」返回，与全量排序取前 K 逐项一致，可重复调用。
- K ≤ 0 时丢弃所有输入并返回空；输入不足 K 个时返回全部；空输入返回空。
- 测试内含朴素参考实现（全量稳定排序取前 K），对固定样例与 1000 组随机数据
  逐项对照，并校验 held 上界、比较次数量级与 100 万条 / K=100 规模。

## 计划新增的能力

```
--k N           选出前 N 名
--generate N    生成 N 个固定种子的条目
--held          打印当前保留的条目数
```
